MathPDF is a clean, elegant PDF reader for Apple platforms, inspired by the simplicity of Preview, but purpose-built for people who write math in annotations.
Core idea:
All notes/comments remain plain text in the PDF, but whenever a note contains math notation (such as `$...$`, `$$...$$`, `\(...\)`, or `\[...\]`), the app displays it as properly rendered math for reading comfort. The stored data stays plain-text and PDF-compatible.

Product experience:
You open a PDF and get a polished document view with a sidebar whose quiet title menu selects one of two modes:

Table of Contents (document outline)
Highlights and Notes (all highlights and annotation notes across the document)
Annotation behavior:
Works with highlights that have attached notes.
Works with box-style note annotations.
Clicking a note icon/box opens a popover for that note.
Notes selected from the sidebar also open in context.
When a PDF carries Preview-style popup companions for highlight notes, MathPDF treats the owning annotation's plain-text contents as authoritative and avoids duplicate in-app note UI. In memory it suppresses PDFKit's popup presentation and renders its own affordance. On disk it preserves or creates a standards-valid reciprocal `/Popup` and `/Parent` relationship. Saving reparses and rejects output whose page, annotation, relationship, or metadata semantics changed unexpectedly.
Math behavior:
Supports common MathJax-style delimiters and broadly compatible math syntax.
Rendering should be forgiving and user-friendly.
If math parsing has issues, the app should fail gracefully (show readable raw text) without noisy error spam.
Editing behavior:
Live preview while typing is not required.
Notes are editable as plain text.
The app should allow creating and editing note annotations naturally as part of the reading workflow.
Per-document preamble/macros:
Each PDF can have its own math preamble (macro definitions, aliases, etc.).
This is a per-PDF setting, not a per-user global preference.
Users can view/edit this preamble from a PDF inspector-style view.
The preamble should travel with the PDF via metadata so another compatible viewer can read it.
Compatibility intent:
Keep annotation content and note storage interoperable with normal PDF tools.
The app adds better rendering and UX, not a proprietary note format.
MathPDF does not create a duplicate `/Text` annotation for a highlight note.
PDFKit's standard page annotation remains visible, while MathPDF owns the one
transient reading surface used inside the app.
Design intent:
A minimal, tasteful, “just works” reader that feels native and uncluttered, while giving technical users first-class math note readability.

Product contract:
- The target is the user's research-PDF workflow: multiple document windows, outlines, search, stable page and zoom navigation, highlighting, box notes, rendered math notes, printing, and trustworthy saving.
- Signature authoring, image editing, cropping, OCR, and comprehensive PDF-form authoring are outside this replacement target.
- Clicking an annotation already visible in the PDF must never change the document's viewport. Sidebar navigation preserves scale and scrolls only as much as needed.
- Note edits are undoable document mutations and use native atomic autosave, with Save As and Revert available. A note popover does not own a separate disk-save workflow.
- The sidebar uses a native list and a title dropdown rather than persistent tabs. Its modes are Table of Contents and Highlights and Notes; bare highlights remain discoverable through extracted source text. The PDF remains the dominant visual surface; preamble editing lives in an optional trailing inspector.
- Existing notes open for reading; only New Note or explicit Edit focuses the plain-text editor. Sidebar rows remain concise and spatially stable while the popover or inspector owns full note content.
- The unified toolbar uses a document title/page subtitle, direct page entry, one grouped zoom control, and an always-visible native search field with contextual result navigation.
- Per-document preambles intentionally support a small annotation-oriented subset: zero-argument aliases, simple parameterized commands, and math operators. Unsupported full-document TeX is ignored gracefully.
- The preamble is stored as a versioned MathPDF marker inside standard PDF Keywords so unrelated metadata survives and non-MathPDF viewers still see ordinary PDF annotations.
